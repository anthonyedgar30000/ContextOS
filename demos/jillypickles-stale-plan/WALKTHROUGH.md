# JillyPickles stale execution-context demo

This demo shows how ContextOS prevents a stale execution context from reaching a
commit or push. It uses a local toy repository named `JillyPickles`; no network
services or external APIs are required.

## Scenario

1. Developer works on BranchA: `feature/clientA`.
2. Context packet is generated for BranchA.
3. AI-assisted plan assumes BranchA remains the active execution context.
4. Developer switches locally to BranchB: `main`.
5. Stale assumptions persist.
6. Unauthorized mutation is attempted against `deploy/production.yml`.
7. ContextOS detects the branch/HEAD mismatch and protected-path violation.
8. Installed pre-commit hook blocks the commit.
9. Audit report is generated by the verification step.

## Run it

From the repository root:

```sh
demos/jillypickles-stale-plan/run_demo.sh
```

By default, the script recreates the local demo repository at:

```text
/tmp/contextos-jillypickles-demo/JillyPickles
```

To use a different parent directory:

```sh
CONTEXTOS_DEMO_WORKDIR=/tmp/my-contextos-demo demos/jillypickles-stale-plan/run_demo.sh
```

## Why this is realistic

The stale-context failure is a common local workflow risk:

- A reviewed context packet is generated for one branch.
- The developer or agent switches branches before applying the plan.
- The staged mutation touches a deployment file that was not in the BranchA
  scope.
- Verification checks local Git state, staged paths, and the ingested session
  context before a commit can proceed.
- The installed pre-commit hook reruns verification and blocks the commit.

The demo intentionally combines two independent safeguards:

- **Context freshness:** `.contextos/session_context.json` records the branch
  and HEAD hash from `contextos ingest`, then verification classifies the
  current context as `FRESH`, `AGING`, `STALE`, or `DIVERGED`.
- **Protected paths:** `verify_cli.py --protected-mode enforce` blocks staged
  changes under `deploy/**`.

The expected result is a non-zero verification exit and a clear remediation:

```text
CONTEXT STALE
Reason:

- session created on feature/clientA
- current branch is main
- HEAD changed after ingestion

Suggested remediation:

1. regenerate context packet
2. run contextos ingest
3. revalidate before commit
```
